# Синхронизация скиллов Hermes между компьютерами — инструкция для начинающего

Эта инструкция — для любого, кто работает с Hermes Agent на одном из трёх
компьютеров (ПК1, ПК2, ноутбук). Опыт в программировании почти не нужен:
достаточно уметь открыть терминал и скопировать в него команду.

---

## 1. Что такое скилл и зачем синхронизация

**Скилл** — это папка с инструкцией для агента Hermes (файл `SKILL.md`) и, иногда,
со скриптами рядом. Скилл объясняет агенту, *как* делать какую-то работу:
скачивать видео, переводить и озвучивать книги, разбирать почту и т.д.

Агент сам дописывает и улучшает скиллы по ходу работы. Чтобы находка, сделанная
на одном компьютере, появилась на двух других, все скиллы хранятся в **одном
общем репозитории на GitHub**. Каждый компьютер держит у себя его копию и
обменивается изменениями через GitHub.

```
   ПК1  ──push──►              ◄──push──  ПК2
        ◄──pull──   GitHub     ──pull──►
                      ▲  │
                 push │  │ pull
                      │  ▼
                    ноутбук
```

- **push** («отправить») — выложить свои изменения на GitHub;
- **pull** («забрать») — получить чужие изменения с GitHub.

## 2. Где что лежит

### Общий репозиторий скиллов

| Что | Где |
|---|---|
| Репозиторий на GitHub (приватный) | https://github.com/Yuri-Sverdlov/HERMES-AGENT-SKILL-ARCHIVE |
| Копия на **каждом** компьютере (путь одинаковый везде) | `E:\_MY-PROGRAMMING\HERMES-AGENT-SKILL-ARCHIVE` |
| Сами скиллы | `...\HERMES-AGENT-SKILL-ARCHIVE\skills\<категория>\<имя скилла>\` |

Hermes подключён к этой папке напрямую. В его настройках
(`%LOCALAPPDATA%\hermes\config.yaml`) есть строки:

```yaml
skills:
  create_dir: E:/_MY-PROGRAMMING/HERMES-AGENT-SKILL-ARCHIVE/skills
```

Это значит: Hermes **читает** скиллы из этой папки и **записывает** туда же новые
и исправленные. Поэтому всё, что агент узнал, сразу оказывается внутри
репозитория — остаётся только отправить это на GitHub.

### Скиллы, которые живут в своих проектах

Некоторые скиллы неотделимы от программы, которую обслуживают, и хранятся в
репозитории этой программы, а не в общем. Hermes подключает их отдельной строкой
`external_dirs` в том же `config.yaml`.

| Скилл | Репозиторий | Папка скилла внутри репозитория |
|---|---|---|
| `home-accounting` (домашняя бухгалтерия) | `Yuri-Sverdlov/HERMES-ALL-IN-ONE` | `projects\FINANCES\skill` |

Такие скиллы синхронизируются вместе со своим проектом: `git pull` / `git push`
делается в папке проекта, а не в общем репозитории.

### Что в репозиторий НЕ кладётся

- **Встроенные скиллы Hermes** (например `computer-use`, `github-*`) — их
  обновляет сам Hermes при своём обновлении.
- **Личные файлы**: выгрузки чатов, документы `.docx` / `.pdf`, архивы `.zip`,
  cookies, ключи и пароли. Файл `.gitignore` в репозитории не даёт их случайно
  отправить, но перед отправкой всё равно смотрите список файлов (раздел 3).
- **Данные для работы скиллов** — книги, шрифты, окружения Python, скачанные
  видео. Скилл объясняет в своём `SKILL.md`, куда их положить на каждом ПК.

## 3. Каждый день: два действия

Все команды ниже вводятся в терминале (PowerShell или Git Bash) — или можно
попросить агента Hermes: «сделай git pull в репозитории скиллов».

### Перед началом работы — забрать свежие скиллы

```
cd "E:/_MY-PROGRAMMING/HERMES-AGENT-SKILL-ARCHIVE"
git pull
```

Ответ `Already up to date.` означает: изменений не было, всё актуально.

### После работы — отправить свои изменения

```
cd "E:/_MY-PROGRAMMING/HERMES-AGENT-SKILL-ARCHIVE"
git status --short
```

Эта команда показывает список изменённых файлов. Просмотрите его глазами:
там должны быть только файлы из `skills\`, `README.md`, `CHANGELOG.md` и т.п.
Если видите личный файл (документ, выгрузку чата) — не отправляйте, сначала
уберите его из папки.

Если список пустой — отправлять нечего, вы закончили. Иначе:

```
git add -A
git commit -m "Коротко: что изменилось и зачем"
git push
```

Проверка, что отправка действительно дошла до GitHub:

```
git rev-parse HEAD
git ls-remote origin main
```

Две строки должны начинаться с **одинакового** длинного кода. Совпали —
изменения на GitHub, другие компьютеры получат их своим `git pull`.

> Для скиллов, которые живут в своих проектах (раздел 2), всё то же самое, только
> `cd` в папку этого проекта.

## 4. Как создать или исправить скилл

Руками ничего копировать не нужно. Просто работайте с агентом:

- **Новый скилл.** Попросите: «сохрани это как скилл». Hermes создаст папку в
  `E:\_MY-PROGRAMMING\HERMES-AGENT-SKILL-ARCHIVE\skills\<категория>\<имя>\`.
- **Исправление.** Попросите: «добавь это в скилл video-fetch». Hermes исправит
  файл там, где скилл лежит, — то есть в репозитории.

После этого выполните «отправить свои изменения» из раздела 3. Если правок много,
делайте отдельный коммит на каждый скилл — так проще понять историю.

Хорошая привычка — одна строка в `CHANGELOG.md`: что добавлено, что изменено и
почему. Git хранит *что* поменялось, а CHANGELOG объясняет *зачем*.

**Скрипты внутри скилла** ссылаются на свою папку через `${HERMES_SKILL_DIR}`,
например `python "${HERMES_SKILL_DIR}/scripts/translate.py"`. Hermes сам
подставляет правильный путь на каждом компьютере, поэтому в скиллах не пишут
пути конкретного ПК вроде `C:\Users\...`.

## 5. Если git выдал ошибку

### `git push` отклонён: `rejected` / `fetch first`

Значит, пока вы работали, с другого компьютера уже отправили изменения. Сначала
заберите их, потом отправьте свои:

```
git pull
git push
```

### `git pull` пишет `CONFLICT`

Это бывает, когда один и тот же файл правили на двух компьютерах. Git не знает,
какую версию оставить, и помечает спорное место в файле так:

```
<<<<<<< HEAD
текст с этого компьютера
=======
текст с другого компьютера
>>>>>>> ...
```

Проще всего попросить Hermes: «в репозитории скиллов конфликт после git pull —
объедини обе версии, сохрани находки с обеих сторон». Если делаете сами:
оставьте нужный текст (обычно — **обе** находки), удалите строки `<<<<<<<`,
`=======`, `>>>>>>>`, затем:

```
git add -A
git commit -m "Объединены правки с двух ПК"
git push
```

### `git pull` пишет, что локальные изменения будут перезаписаны

У вас есть неотправленные правки. Сначала отправьте их (раздел 3, «после
работы»), потом повторите `git pull`.

### Не уверены, что делать

Ничего не удаляйте. Скопируйте текст ошибки агенту Hermes и спросите, что он
значит. Пока вы не сделали `push`, на GitHub и на других компьютерах ничего не
меняется.

## 6. Подключение нового компьютера

Делается один раз на машину. Удобнее всего попросить агента: «подключи этот ПК к
репозиторию скиллов по ИНСТРУКЦИЯ-СИНХРОНИЗАЦИЯ-СКИЛЛОВ.md, раздел 6» — он
выполнит шаги и покажет результат. Сами шаги:

1. **Скачать репозиторий** в общую папку:
   ```
   cd "E:/_MY-PROGRAMMING"
   git clone https://github.com/Yuri-Sverdlov/HERMES-AGENT-SKILL-ARCHIVE.git
   ```
2. **Сделать резервную копию** папки `%LOCALAPPDATA%\hermes\skills` (просто
   скопировать её целиком в другое место).
3. **Если на этом компьютере уже были свои скиллы** — сначала перенести их
   (новые скиллы и свежие правки) в репозиторий и отправить на GitHub. Иначе
   находки этого ПК потеряются. Это работа для агента: «сравни мои локальные
   скиллы с репозиторием и перенеси то, чего там нет или что новее».
4. **Подключить Hermes к папке.** В `%LOCALAPPDATA%\hermes\config.yaml` в
   разделе `skills:` добавить строку:
   ```yaml
   skills:
     create_dir: E:/_MY-PROGRAMMING/HERMES-AGENT-SKILL-ARCHIVE/skills
   ```
5. **Удалить старые локальные копии** этих же скиллов из
   `%LOCALAPPDATA%\hermes\skills\` — тех, что теперь есть в репозитории.
   (Встроенные скиллы Hermes не трогать.)
6. **Подключить проектные скиллы**, которые нужны на этой машине (раздел 2):
   склонировать репозиторий проекта и добавить путь к папке скилла в
   `external_dirs`.
7. **Полностью перезапустить Hermes** и проверить:
   ```
   hermes skills list
   ```
   Скиллы из репозитория отмечены в колонке источника как `create_dir`,
   проектные — как `external`.

---

## 7. Чего нельзя делать

| Нельзя | Почему |
|---|---|
| Копировать скиллы из репозитория в `%LOCALAPPDATA%\hermes\skills` | Если скилл с тем же именем лежит и там, и в репозитории, Hermes берёт **локальную** копию, а правки уходят мимо GitHub |
| Править скиллы, не сделав сначала `git pull` | Получите лишний конфликт с изменениями другого компьютера |
| Заканчивать работу без `git push` | Ваши находки останутся только на этом компьютере |
| Отправлять личные файлы, ключи, пароли | Репозиторий — общее хранилище; удалённый из него файл остаётся в истории |
| Писать в скиллах пути конкретного компьютера (`C:\Users\...`) | На другом ПК путь будет другим; используйте `${HERMES_SKILL_DIR}` |
| Класть встроенные скиллы Hermes в репозиторий | Их обновляет сам Hermes, копия в репозитории устареет |

## 8. Шпаргалка

```
cd "E:/_MY-PROGRAMMING/HERMES-AGENT-SKILL-ARCHIVE"

git pull                         # утром: забрать свежее

git status --short               # вечером: что изменилось (проверить глазами)
git add -A
git commit -m "что и зачем"
git push                         # отправить на GitHub

git rev-parse HEAD               # проверка: два одинаковых кода =
git ls-remote origin main        # всё дошло до GitHub

hermes skills list               # какие скиллы видит Hermes и откуда
```

Подробные правила для тех, кто сопровождает репозиторий, — в `SYNC-LOGIC.md`;
список скиллов — в `README.md`; история изменений — в `CHANGELOG.md`.
