# Оживить проект на ПК (после переезда папок или на новой машине)

Когда: путь из `config.yaml` или документа ведёт в несуществующую/пустую папку,
или Юрий просит «сделать проект живым здесь».

## Порядок

1. **Найди мёртвые пути.** В `%LOCALAPPDATA%\hermes\config.yaml`: `skills.external_dirs`,
   `skills.create_dir`, `terminal.cwd`. Проверь каждый `ls`; существующая папка
   должна быть git-клоном (`git -C <путь> log -1`), а не пустой заготовкой.
2. **Клон в пустую папку, которую указал Юрий** (`git clone <url> <путь>`) —
   это безопасно, можно делать сразу. Проверь, есть ли в клоне та подпапка,
   на которую ссылался конфиг (напр. `.hermes/skills`): если её нет в git — скилл
   потерян, ищи имя в `skills/.usage.json` и спроси про копию на другом ПК.
3. **Правка `config.yaml`** — после бэкапа файла; правь точечной заменой
   строки через Python (сохраняя CRLF), не `patch`/`write_file`: diff печатает
   соседние строки с ключами. Мёртвый путь без замены — удали. Проверка:
   `yaml.safe_load` + `hermes skills list` (скилл с источником `external`).
4. **Зависимости — по `DEPLOY.md`/README проекта.** Для Python-венва бери версию
   из `py -0p`, совместимую с запиненными пакетами (не самую свежую: для новой
   версии часто нет колёс) — `<python> -m venv venv` там, где его ждут
   bat-скрипты; `npm install --no-audit --no-fund`.
5. **`.env`** — скопируй из `.env.example`, убедись, что git его игнорирует.
   Ключи не вписывай и не ищи по другим `.env` — скажи Юрию, какую строку
   заполнить и где взять ключ.
6. **Дымовая проверка без долгого сервера в фореграунде:** фронт — сборка
   (`node node_modules/vite/bin/vite.js build --outDir "$TMPDIR/..."`, чтобы не
   мусорить в репо); бэкенд — `terminal(background=true)` на свободном порту,
   `curl` реального API-эндпоинта (не `/`), затем `process_manage kill`. В отчёт —
   что именно ответил эндпоинт.
7. **Документы проекта:** обнови только действующие указания пути
   (`CONTEXT.md`, правила в `AGENTS.md`) в форме «ПК1 — …, ПК2 — …»; журналы и
   архивные отчёты не переписывай. Перед push публичного репо — в коммите
   только пути. Commit + push + сверка HEAD с `git ls-remote`.

## Грабли

- Тесты проекта могут требовать личные файлы вне git (банковские выписки
  для `selftest.py`) — падение на `FileNotFoundError` такого файла отчитывай как
  «не хватает личного фикстура», а не как сломанный код.
- Перед переименованием SQLite-файла закрой своё же соединение в сессионном
  интерпретаторе — на Windows открытый файл не переименуется (WinError 32), а
  неудачный `shutil.move` оставляет копию-дубль, её надо удалить.
- Переменная через `setx` попадает только в новые процессы: проверяй
  `reg query HKCU\Environment /v <ИМЯ>` и тестируй скрипт с явно переданным `env`.
