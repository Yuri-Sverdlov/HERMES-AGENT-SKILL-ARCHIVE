# Синхронизация скиллов Hermes между ПК через GitHub

Аудит копий по хешам; общий git-клон, подключённый к Hermes через
`skills.create_dir` + `skills.external_dirs`.

## When to Use

Аудит/наведение порядка в скиллах, перенос скилла на другой ПК, подключение
нового ПК к общему репо скиллов, сравнение архивных копий с живыми скиллами.

У Юрия 3 машины (ПК1, ПК2, ноутбук). Цель: находки и новые скиллы с любой машины
доступны на остальных. Общий хаб скиллов — **приватный** репозиторий
`Yuri-Sverdlov/HERMES-AGENT-SKILL-ARCHIVE`, клон на **всех** ПК по одному пути
`E:\_MY-PROGRAMMING\HERMES-AGENT-SKILL-ARCHIVE` (скиллы — в `skills/<категория>/<имя>/`).
Правила синхронизации описаны в его `SYNC-LOGIC.md` —
прочитай его перед любыми изменениями. Старый хаб `Yuri-Sverdlov/HERMES-AGENT`
(архитектор↔кодер, guides/) содержит устаревшие копии `SOURCES-ARCHIVE*` — не
источник правды.

## Целевая схема (не копии, а подключённый git-клон)

Копии-зеркала устаревают за недели (все найденные копии архива оказались старее
живых скиллов). Поэтому клон репо подключается к Hermes напрямую в `config.yaml`
каждого ПК:

```yaml
skills:
  create_dir: E:/_MY-PROGRAMMING/HERMES-AGENT-SKILL-ARCHIVE/skills   # читается И сюда же пишутся новые скиллы
```

`create_dir` сам по себе сканируется как полноценная папка скиллов — дублировать
её в `external_dirs` не нужно (`external_dirs` оставь для чужих репо вроде
`HERMES-ALL-IN-ONE`). Curator работает только с локальной папкой профиля, так что
скиллы из репо он не архивирует.

`skill_manage patch` правит скилл там, где он лежит → правки тоже идут в репо.
Синк = `git pull` в начале, `git add -A && git commit && git push` в конце.
Справка: `website/docs/user-guide/features/skills.md` (external_dirs, create_dir).
Рабочий образец: `home-accounting` из `HERMES-ALL-IN-ONE` через `external_dirs`.

## Процедура

1. **Аудит.** `git status`, `git fetch`, ahead/behind в каждом хабе; `gh repo list
   Yuri-Sverdlov` — ищи ВСЕ репо со словами HERMES/SKILL (легко пропустить
   отдельный архив-репо и предложить построить его заново). Читай их README /
   SYNC-LOGIC: `gh api repos/<owner>/<repo>/contents/<file> --jq .content | base64 -d`.
2. **Сравни копии по хешам, не по датам** — `python scripts/audit_skills.py <copy1> <copy2> ...`
   (копии ↔ живой `%LOCALAPPDATA%\hermes\skills`; для разошедшихся печатает mtime
   и число строк, чтобы понять, где свежее).
3. **Отфильтруй встроенные скиллы.** Синкаются только личные: исключи то, что
   есть в `hermes-agent/skills`, `optional-skills` и `.bundled_manifest`. Скиллы в
   `.archive/` выключены curator'ом — переносить ли их, спроси.
4. **Приватность до пуша.** Проверь видимость (`gh repo view --json visibility`)
   и дерево на личные файлы (чаты WhatsApp, zip, docx, `app.py`, номера
   телефонов) и ключи. `.gitignore` должен действовать на весь репо, а не на одну
   подпапку. Перевод репо в приватный не чистит историю — скажи об этом.
5. **Сведение версий** в клоне: свежая живая версия перезаписывает архивную;
   переименованные/слитые скиллы (напр. старые загрузчики → `video-fetch`,
   `video-batch-runner`, `video-source-resolve`) сопоставляй по смыслу и
   вливай находки в новое имя, старую папку удаляй. Категории — как в Hermes
   (`media/<skill>/`).
6. **Переключение ПК:** бэкап локальных скиллов → правка `config.yaml` →
   **удалить локальные дубли** перенесённых скиллов → `hermes skills list` /
   `skills_list` показывает их из репо.
7. **Онбординг другого ПК:** сначала его уникальные скиллы/правки коммитятся и
   мерджатся в репо, только потом подключение и удаление локальных копий —
   иначе его находки затрутся.

## Грабли

- Precedence: `project → local skills/ → create_dir → external_dirs`. Если имя
  есть и локально, и в репо — локальная копия молча затеняет репо, и правки
  уходят не туда. Всегда удаляй локальный дубль после переноса.
- Не предлагай свой export/import-скрипт и хеш-манифест — `create_dir` +
  `external_dirs` + git делают это без копирования; история git показывает,
  что новее.
- Таймстампы врут после облачного/robocopy-копирования — сравнивай хеши.
- Жёсткие пути `C:/Users/Yuri/AppData/Local/hermes/skills/...` в SKILL.md ломаются
  после переезда в репо — заменяй на `${HERMES_SKILL_DIR}/scripts/...`.
- Отличай личные скиллы от встроенных по содержимому: `computer-use-pc2` оказался
  старой копией встроенного `computer-use` (тот же `name:`), а скиллы с датой
  установки Hermes и автором не Юрий — бывшие встроенные. Hub-установки
  (`.hub/lock.json`) не переносим — ставятся командой.
- После правки скилла в репо — сразу `git commit && git push` в
  `E:\_MY-PROGRAMMING\HERMES-AGENT-SKILL-ARCHIVE`, сверка HEAD с `git ls-remote`.
- Шаги, меняющие `config.yaml` или удаляющие скиллы, — только после бэкапа и
  явного «да» пользователя; аудит и подготовку клона можно делать сразу.
- Юрий может прислать разбор другого агента: сверь его факты со своими
  (хеши), явно перечисли, что тот пропустил и что предлагаешь заменить — с
  обоснованием, а не просто согласие.
- Ответы — по-русски; итог аудита таблицей «скилл / где свежее / что совпадает»,
  в конце 2–4 конкретных вопроса на решение (обычным текстом, не через clarify).
