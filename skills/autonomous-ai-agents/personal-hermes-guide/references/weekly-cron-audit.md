# Недельный cron-обход гайда — процедура

Задача: раз в неделю просмотреть свежие сессии, найти НОВЫЕ фундаментальные
находки про Hermes и, если они есть, предложить пользователю занести их в
`Guide-to-Hermes.md` / `Guide-to-Hermes-2.md`. Если нечего — `[SILENT]`.

## Порядок (отработан на прогоне 2026-09-16)

1. **Прочитай сами гайды** (`read_file` по `~/hermes-guides/Guide-to-Hermes.md` и
   `-2.md`), чтобы точно знать, что там уже ЕСТЬ. Без этого легко предложить
   дубль.
2. **Определи период.** Найди предыдущую cron-сессию и её `started_at` —
   всё позже этой отметки считается «новым»:
   `python scripts/scan_sessions.py --last-cron`
   Прошлый прогон часто заканчивается `[SILENT]` — значит с тех пор ничего не
   записывали, и порог можно отодвинуть до даты предыдущего обхода.
3. **Перечисли сессии периода** (не только те 3, что показывает browse):
   `python scripts/scan_sessions.py --days 8`
   Обрати внимание на `source`: `cli` / `tui` / `telegram` / `cron` / `subagent`.
   Крупные сессии (300+ сообщений) почти всегда содержат больше всего механики.
4. **Сузь выборку.** Сначала дампни только `role='user'` сообщения — они задают
   темы и содержат жалобы/симптомы («почему долго нет ответа», «Ctrl+C
   перезапускает сессию»). Затем `--grep` по маркерам грабель Hermes-уровня:
   `Ctrl+C`, `max_tokens`, `too large`, `timed out`, `hermes config`,
   `hermes pets`, `/copy`, `update --check`, `mouse_tracking`, `[SILENT]`,
   `Operation interrupted`, `Pending approval`, `Background process`.
5. **Отфильтруй шум.** Многое в сессиях — про проекты пользователя (whisper,
   VideoLingo, скачивание видео), а не про Hermes. Записывать в гайд только то,
   что про **сам Hermes**: интерфейсы, конфиг, лимиты, апдейты, команды, режимы
   работы агента. Проектные грабли → в навык проекта, не в гайд.
6. **Проверь кандидата на новизну** — поищи его в обоих файлах гайда. Уже есть →
   не предлагать (максимум уточнить формулировку в стабильном разделе).
7. **Маршрутизируй** находки:
   | Тип находки | Куда |
   |---|---|
   | принцип / грабля / нарратив | `Guide-to-Hermes.md` — таблица «Грабли» + датированная запись в «Журнал сессий» |
   | рабочая команда | `Guide-to-Hermes-2.md` → «Полезные команды» |
   | новый термин | `Guide-to-Hermes-2.md` → «Глоссарий» |
   | сравнение моделей / цена-качество | `Guide-to-Hermes-Models.md` |
8. **Отчёт пользователю** (по-русски, компактно): сгруппировать находки, у каждой
   1–3 строки конкретики (симптом → причина → решение, реальный текст ошибки),
   пометить слабые/спорные отдельно («на грани — можно не записывать»), и в конце
   явный вопрос «занести?» с указанием маршрутизации. **Не писать в файлы без
   разрешения** — это крон, ответ придёт пользователю в его канал.
9. Если находок нет/они тривиальны — финальный ответ ровно `[SILENT]`, без
   текста и без «а ещё...». Ничего не комбинировать.

## Грабли исполнения в cron

- `execute_code` — жёстко заблокирован («Cron jobs run without a user present to
  approve it»). Не пытаться.
- inline `python -c "..."` через `terminal` — уходит в `pending_approval` и
  **висит** (подтверждать некому). Путь: `write_file` скрипта → `python file.py`.
- `session_search` на широком запросе возвращает 100–150 КБ и персистится в файл —
  для обзорных задач это дороже, чем читать `state.db` скриптом.
- Terminal может не находить диск `G:` (`cd G:/...` → «No such file or directory»),
  хотя файловые инструменты гайды через junction `~/hermes-guides/` читают и
  пишут. Гайды править файловыми инструментами; `git commit/push` — только
  напомнить пользователю, не блокироваться.
- BOM: любая правка .md — с UTF-8 BOM (см. SKILL.md, правило жёсткое).

## Формат находки (критерий «достойно гайда»)

Достойно: фундаментальная механика Hermes, неочевидная грабля с внятной причиной,
рабочая команда, термин уровня глоссария. Примеры из прогона 2026-09-16:
`Ctrl+C` в CLI/TUI = выход из сессии (а `display.copy_shortcut` — no-op);
`/copy [N]`; аргументы tool-call >~8K токенов → «stream timed out»;
прерванный foreground-`sleep` убивает фоновые процессы (`kill_all`);
`hermes pets install/doctor`; `hermes config` не имеет подкоманды `list`.

НЕ достойно: разовые ошибки окружения (нет бинарника, не тот путь), транзиентные
сбои, которые уже прошли, проектные детали, «сегодня сделали X».
