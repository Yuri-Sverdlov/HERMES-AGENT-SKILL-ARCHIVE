# Текст со страниц-читалок → локальные файлы

Класс задачи: Юрий даёт список ссылок на произведения онлайн-библиотеки
(author.today, аналоги) и просит «скачать каждую книгу в отдельный файл и сложить
в папку». Результат — по одному чистому текстовому файлу на произведение в
указанной папке, без обвязки сайта, с проверенной полнотой.

## When to Use
- «Скачай по этим ссылкам каждую книгу в отдельный файл», «сложи в папку».
- Список книг/статей лежит файлом рядом с местом, куда надо положить результат.
- Нужен текст для дальнейшего конвейера (перевод → `book-translate-and-voice`).

## Шаг 0. Правило доступа — сначала выяснить, потом качать

Никогда не пытайся обойти платный доступ. Пройди по ссылкам и определи категорию
каждого произведения, **докладывая таблицей, что доступно, а что нет**:

| Категория | Что делать |
|---|---|
| Свободно читается | можно сохранить локально **по явной просьбе Юрия**, для личного чтения |
| Нужна только регистрация | нужен его аккаунт: вход — через маскированное окно хранилища (`browser_vault action=save_login`), пароль в чат не спрашивать и не вводить |
| Подписка на автора / платно / «для друзей» | **не трогать**. Сказать прямо: доступ закрыт, обход — это обход автора и площадки, решение принимает Юрий |

Формулировка в отчёте: «это копия текста из читалки (свободное чтение), а не
официальная кнопка „Скачать“ (она за подписку на автора)». Не выдавать результат за
официальную загрузку.

## Шаг 1. Проверка доступа без браузера (30 секунд на произведение)

Плейн-HTTP отдаёт страницу произведения целиком, а признаки доступа там
**HTML-экранированы** (`&quot;`) — сперва `html.replace("&quot;", '"')`, потом regex:

- `"allowDownloads":(true|false)` — разрешена ли загрузка вообще;
- `"downloadText":"…"` — текст условия (в нём прямым текстом: что именно нужно —
  регистрация, подписка на автора и т.п.);
- `"isPurchased"`, `"price"` — покупка.

Заголовки: обычный браузерный `User-Agent` + `Referer: https://author.today/`,
пауза ~1 с между запросами (иначе 403). Произведение, закрытое для анонимов,
отвечает **403** — это и есть ответ «нужен статус друга/покупка», не обходи его.

Точную конкретику сайта см. `references/author-today.md`.

## Шаг 2. Список глав

Оглавление лежит в HTML страницы произведения: собрать
`re.findall(r'/reader/<ID>/(\d+)')` в порядке появления (дубли убрать
`dict.fromkeys`). Пустой список = одностраничное произведение → использовать
`/reader/<ID>`. Заодно вытащить названия глав (текст ссылок в оглавлении) — они
пойдут заголовками разделов.

## Шаг 3. Текст берётся из отрендеренного DOM

Тело читалки рендерится скриптом на клиенте, поэтому в исходном HTML текста НЕТ —
не тратить время на плейн-HTTP для главы. Текст: `document.querySelector('#reader').innerText`
в браузере (селектор уточнить под сайт). Проверка, что это действительно текст, а не
заглушка: длина в несколько тысяч знаков и осмысленное начало.

## Шаг 4. Сбор по одной главе, с записью на диск сразу

- Одна навигация на главу: `goto_url` → `wait_for_load` → пауза ~2 с → чтение.
- **Не складывать длинный async-цикл внутрь одного `js()`**: `Runtime.evaluate`
  живёт с бюджетом порядка 5 секунд, и вызов падает на середине. Вместо этого
  батч ~10 навигаций на один вызов браузера.
- Каждую главу сразу писать в отдельный файл рабочей папки
  (`…\<site>\raw\<ID>-<chapterId>.txt`) — прогресс переживает таймаут, повтор не нужен.
- Планирование: ~5–6 с на главу; 20 глав ≈ 2 мин.

## Шаг 5. Возрастной гейт (18+)

Если текст короче ~300 знаков — на странице стоит подтверждение возраста: нажать
кнопку с текстом вида «Да, мне есть 18», подождать и перечитать. Без клика
вернётся только обвязка.

## Шаг 6. Чистка обвязки читалки

Текст приходит с шапкой и хвостом интерфейса. Убрать:
1. шапку — построчный блок-лист: `Оглавление`, `Описание`, `Вернуться на сайт`,
   `Настройки`, `Яркость`, `Размер`, `Поля`, `Высота строк`, `Шрифт`,
   `Перенос текста`, `Своя цветовая схема`, `Взрослый контент`, `Мне нет 18`,
   `Да, мне есть 18` (срезать, пока строки в списке или пустые);
2. хвост — строки вида `← Предыдущая глава` / `Следующая глава →`
   (`re.match(r"^\s*(←.*|.*→)\s*$")`);
3. `\xa0` → обычный пробел (иначе поиск и чтение ломаются);
4. три и более переводов строки → двойной перевод строки.

## Шаг 7. Сборка файла (один файл на произведение)

- Шапка файла: название, автор, `Источник: <url> (свободный доступ на сайте)`,
  дата сохранения, «для личного чтения», число знаков.
- Главы — с заголовками из оглавления и разделителем из дефисов.
- Имя — **ASCII** (`NN-Translit-Title-Author.txt`), нумерация как в исходном
  списке книг (пропуски номеров лучше, чем перенумерация: видно, каких книг нет).
- Кодировка — **UTF-8 с BOM** (`encoding="utf-8-sig"`), как в остальных его
  документах; `write_file` BOM не ставит, писать питоном.
- Рядом с исходным списком книг, в ту же папку, которую назвал Юрий.

## Шаг 8. Проверка (без неё отчёт не готов)

1. **Полнота:** сравнить знаки в файле с заявленным на сайте размером («Размер:
   N зн.») — расхождение в пределах пары процентов (заголовки, разделители) значит
   «всё собрано»; заметный недобор = пропущена глава.
2. **Чистота:** grep по файлам на служебные слова (`Оглавление`, `Настройки`,
   `Вернуться на сайт`, `Мне нет 18`, `оплатите доступ`, `Зарегистрируйтесь`, `→`, `←`) —
   должно быть **ноль** совпадений.
3. **Середина книги:** прочитать пару сотен знаков из середины — там должен быть
   содержательный текст, а не заглушка «книга в платном доступе».

## Шаг 9. Картинки и Word-версия (отдельный заказ после текстов)

text-capture теряет картинки; их добывают так:
1. остаться на странице главы и забрать `#reader.innerHTML` (одна навигация) → сохранить в `…\<site>\html\<ID>.html`;
2. разметка → markdown рекурсивным обходом блоков на `lxml`, `<img src>` → `![]()`. **Не добавлять рядом с рекурсивным
   вызовом его же `ch.text`** — текст задвоится (`«Благодарю К. М.«Благодарю К. М.»`); теги `strong/b`, `em/i` несут свой текст внутри;
3. картинки качать плейн-HTTP с `Referer` страницы читалки (работает); часть лежит на CDN `<site>.author.today` — качать оттуда же;
4. число картинок проверять **по DOM** (`#reader img`), а не по странице произведения: в HTML страницы видны не все
   (у Юрия было «шесть», реально 16). Проверять **каждую** главу — картинка могла попасть в любую;
5. одинаковые картинки по md5 внутри произведения — нормально (автор повторяет схему), обе вставки оставлять;
6. pandoc собирает docx с внедрёнными картинками: `![]()` с абсолютным путём через **прямые слэши**, для
   многоглавых — `--toc --toc-depth=1`; файлы .docx рядом с .txt, имена ASCII.

Проверка .docx (не на глаз): считать в архиве `word/media/*`, уникальные `r:embed` (должны совпасть с числом картинок)
и `<w:drawing>`; порядок — найти в `document.xml` подписи («Таблица 1/2») и убедиться, что картинки стоят рядом с ними.
`<w:pict>` — это VML-дубль от pandoc в том же абзаце, **не** второй экземпляр картинки. Одна картинка-таблица
= отдельный файл на несколько страниц (у «Таблицы 1» было две).

## Питфоллы

- **Картинки не сохраняются.** `innerText` отдаёт только текст: таблицы и
  иллюстрации, опубликованные как изображения, теряются (в файле останутся только
  подписи «Таблица 1»). Сказать об этом прямо и предложить вытащить картинки
  отдельно / собрать Word с ними — не молчать и не делать вид, что текст полный.
- Число глав брать из оглавления, а не из первой страницы читалки: читалка
  показывает одну главу и ссылку «дальше», по ней полноту не оценить.
- Произведение со статусом «в процессе» дописывается автором — фиксировать в
  шапке файла дату сохранения, иначе позже не понять, какая версия текста у тебя.
- Список книг, приложенный к задаче, читать целиком: в нём бывают графы «Доступ»
  и «Размер» — это готовый план проверки и источник ожидаемых значений.
- Отвечать по-русски, не мешать результат с другими задачами и не переписывать
  сам список книг.
