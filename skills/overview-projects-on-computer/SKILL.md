# Overview Projects On Computer

Поддерживает базу знаний проектов (`PROJECTS_KNOWLEDGE_BASE`) в актуальном состоянии при перемещении проектов между папками. Обновляет ТОЛЬКО адреса (пути) — статусы, цели, функционал и GitHub-репозитории сохраняются.

## Когда использовать

- Пользователь говорит: «Overview projects», «обнови пути проектов», «проект переехал», «я переместил папки».
- Пользователь задаёт верхнюю папку (например `G:\AI`), внутри которой лежат подпапки `_MY_PROGRAMMING*`.

## Как работает (архитектура)

База хранится в `references/projects.json`. Ключ — **нормализованное имя проекта** (стабильно), поле `dirs` — список текущих путей (единственное, что меняется при переезде).

```
projects.json:
{
  "meta": {"top_folder": "G:/AI", "github_user": "Yuri-Sverdlov", "updated": "..."},
  "projects": {
    "POST-MAIL-AUTOMATION": {
      "name": "POST-MAIL-AUTOMATION",
      "repo": "POST-MAIL-AUTOMATION",   ← не трогаем
      "status": "живой",                ← не трогаем
      "purpose": "...",                 ← не трогаем
      "func": "...",                    ← не трогаем
      "lang": "Python",                 ← не трогаем
      "note": "...",
      "dirs": ["G:/AI/_MY_PROGRAMMING"]  ← ОБНОВЛЯЕТСЯ при переезде
    }
  }
}
```

## Шаги выполнения

1. Получи верхнюю папку от пользователя (или используй `meta.top_folder` из JSON, если она не менялась).
2. Запусти скрипт:
   ```
   C:/Python311/python "<skill_dir>/scripts/update_projects.py" "G:/AI"
   ```
   (путь в кавычках, Windows-стиль; подставь актуальную верхнюю папку)
3. Скрипт:
   - сканирует `_MY_PROGRAMMING*` подпапки внутри верхней папки;
   - сопоставляет проекты по имени (регистронезависимо, `_`/`-` эквивалентны);
   - обновляет `dirs`; добавляет новые проекты (авто-детект статуса по дате и цели из README); помечает исчезнувшие как «НЕ НАЙДЕН»;
   - перезаписывает `projects.json`;
   - перегенерирует выходные файлы в `C:/Users/Yuri/Documents/PROJECTS_KNOWLEDGE_BASE/`: `README_проекты.md`, `СИРОТЫ_не_на_GitHub.md`, `Word_*.docx`.
4. Сообщи пользователю: сколько путей обновлено, какие новые проекты, какие не найдены.

## Важные правила

- **GitHub НЕ пересканируется.** Обновляются только локальные пути. Репо и метаданные берутся из JSON как есть.
- **Ключ — имя проекта**, а не путь. Нормализация: `re.sub(r"[\s_\-]+", "-", name).upper().strip("-")`.
- **Дубликаты** (один проект в двух папках, напр. `POST-MAIL-AUTOMATION` в `_MY_PROGRAMMING` и `_MY_PROGRAMSING`) → `dirs` содержит оба пути.
- **Корневые проекты** (лежащие прямо в верхней папке, вне `_MY_PROGRAMMING*`) не трогаются — их пути сохраняются.
- **Опечатка** `_MY_PROGRAMSING` учитывается автоматически (префикс `_MY_PROGRAM` ловит и `_MY_PROGRAMMING`, и `_MY_PROGRAMSING`).
- Скилл работает для любой верхней папки — можно указать путь на компьютере 1 (например `D:\AI`), и он пересоберёт базу под ту машину.

## Проверка

- [ ] `projects.json` перезаписан с новой датой `updated`
- [ ] Пути в `dirs` совпадают с фактическим расположением на диске
- [ ] README / сироты / Word перегенерированы
- [ ] Метаданные (статус/цель/функционал/репо) не изменились для существующих проектов

## Pitfalls

1. **Запуск через системный Python** (`C:/Python311/python`), не venv Hermes — иначе нет `python-docx`.
2. **Путь с пробелами** — оборачивай в кавычки.
3. **Перенос на другой компьютер** — верхняя папка другая (например `D:\AI`); просто передай её в скрипт, JSON обновится под новую машину.
