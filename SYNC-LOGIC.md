# Логика репозитория скиллов — синхронизация, обновление, онбординг ПК

Как устроен и как живёт `HERMES-AGENT-SKILL-ARCHIVE`. Читать всем, кто трогает
скиллы на любом устройстве (ПК1, ПК2, ноутбук).

---

## 1. Зачем

Обмениваться личными скиллами Hermes между устройствами через один **приватный**
GitHub-репозиторий: https://github.com/Yuri-Sverdlov/HERMES-AGENT-SKILL-ARCHIVE

## 2. Единственная правда — этот репозиторий (с 2026-10-29)

Раньше правдой была локальная `%LOCALAPPDATA%\hermes\skills\`, а архив —
её зеркалом, которое копировали вручную. Итог: все найденные копии архива
(4 штуки на ПК1) оказались старее живых скиллов, а на разных ПК скиллы
разъехались.

Теперь клон репозитория **подключён к Hermes напрямую** на каждом ПК:

```yaml
# %LOCALAPPDATA%\hermes\config.yaml
skills:
  create_dir: G:/_MY-PROGRAMMING_1/HERMES-AGENT-SKILL-ARCHIVE/skills
```

- Hermes читает скиллы из этой папки (`create_dir` сканируется как полноценная
  папка скиллов, в `external_dirs` её дублировать не надо).
- `skill_manage create` пишет новые скиллы сюда.
- `skill_manage patch` правит скилл там, где он лежит, — то есть тоже здесь.
- Curator работает только с локальной папкой профиля и скиллы репо не архивирует.

**Копирования между папками больше нет.** Синхронизация — это git.

### Ловушка приоритета

Порядок поиска скиллов: `проект → локальная %LOCALAPPDATA%\hermes\skills → create_dir → external_dirs`.
Если скилл с тем же именем лежит и локально, и в репо — **локальная копия молча
побеждает**, а правки уходят в неё, мимо git. Поэтому после подключения локальные
дубли удаляются (§5, шаг 5).

## 3. Ежедневный цикл

```bash
cd /g/_MY-PROGRAMMING_1/HERMES-AGENT-SKILL-ARCHIVE
git pull                      # перед работой
# ... работа в Hermes: скиллы создаются и правятся прямо здесь ...
git add -A
git status --short            # глазами: нет ли личных файлов и мусора
git commit -m "..."
git push
git rev-parse HEAD; git ls-remote origin main   # хеши должны совпасть
```

Push сообщил «успех» — это не доказательство; совпадение HEAD — доказательство.

Конфликт при `pull` (один скилл правили на двух ПК) решается обычным merge —
оставить обе находки, а не одну из версий.

## 4. Правила содержимого

| Случай | Что делаем |
|---|---|
| Новый личный скилл | Создаётся агентом сразу здесь (`create_dir`) |
| Скилл переименован / слит | Новое имя добавляем, находки старого вливаем в него, старую папку удаляем |
| Скилл устарел | Удаляем папку (история остаётся в git) |
| Встроенный скилл Hermes | **Не кладём** — его обновляет Hermes |
| Hub-скилл (`hermes skills install ...`) | Не кладём — ставится командой на каждом ПК |
| Данные конкретного ПК (пути, инвентарь) | Не хардкодить; путь к своим скриптам — `${HERMES_SKILL_DIR}` |
| Чаты, выгрузки, документы, cookies, ключи | **Никогда** (`.gitignore`) |

Каждая заметная синхронизация — запись в `CHANGELOG.md` (что добавлено/
обновлено/переименовано/удалено и почему; git показывает строки, CHANGELOG — смысл).

## 5. Подключение нового ПК (или ПК, где уже есть свои скиллы)

Порядок важен: **сначала** находки ПК попадают в репо, **потом** подключение.
Иначе уникальные правки этого ПК затрутся.

1. `git clone https://github.com/Yuri-Sverdlov/HERMES-AGENT-SKILL-ARCHIVE.git`
   в `E:\_MY-PROGRAMMING\`.
2. Бэкап: скопировать `%LOCALAPPDATA%\hermes\skills` целиком в сторону.
3. Сверить личные скиллы ПК с репо **по хешам, не по датам**
   (`skills/autonomous-ai-agents/hermes-skills-cross-pc-sync/scripts/audit_skills.py`).
   Для каждого: новее в репо → ничего; новее локально → перенести в репо;
   старое имя, которое в репо переименовано → влить находки в новое имя.
   Новые скиллы ПК → добавить в репо. Commit + push.
4. В `config.yaml` прописать `skills.create_dir` (см. §2).
5. Удалить из `%LOCALAPPDATA%\hermes\skills\` все папки скиллов, которые теперь
   есть в репо, и старые имена, заменённые новыми.
6. `/new` в Hermes, проверить `hermes skills list` — скиллы репо на месте,
   предупреждений о затенении (shadowed) нет.

Зависимости (Python-пакеты, Tesseract, ffmpeg, aria2c) — в `README.md`.

## 6. Технические грабли

- Копировать в git-bash через `cp -r`; **не** robocopy в bash-цикле с `$n` —
  переменная не раскрывается, и robocopy создаёт мусорную папку `skills$n`.
- После копирования чистить `__pycache__`/`*.pyc` (`.gitignore` их и так режет).
- Таймстампы врут после облачного/robocopy-копирования — сравнивать хеши.
- Перевод репо в приватный не чистит историю: файлы, когда-либо закоммиченные
  (в т.ч. удалённый чат WhatsApp из первых коммитов), остаются в истории.
