# Логика архива скиллов — синхронизация, обновление, перенос

Этот файл описывает **как устроен и как живёт** архив `HERMES-AGENT-SKILL-ARCHIVE`:
откуда берутся скиллы, как решается какая версия свежее, как это едет в GitHub
и зачем нужен CHANGELOG. Читать всем, кто трогает архив на любом из устройств
(компьютер 1, компьютер 2, ноутбук).

---

## 1. Зачем этот архив существует

Обмениваться скиллами Hermes Agent между несколькими устройствами (компьютер 1,
компьютер 2, ноутбук) через один общий GitHub-репозиторий:
**https://github.com/Yuri-Sverdlov/HERMES-AGENT-SKILL-ARCHIVE** (публичный).

Раньше эта папка жила внутри дерева `HERMES-AGENT` и пушилась в старый репозиторий
`HERMES-AGENT` вместе со всем остальным. Теперь она вынесена в самостоятельную папку
`F:\_MY_PROGRAMMING\HERMES-AGENT-SKILL-ARCHIVE` под отдельный репозиторий — пушится
только она, без родительского дерева.

---

## 2. Единственная правда — директория Hermes

Все скиллы сначала создаются и дорабатываются в рабочей директории Hermes:

```
C:\Users\<пользователь>\AppData\Local\hermes\skills\
```

Эта директория — **единственный источник правды**. Архив
`HERMES-AGENT-SKILL-ARCHIVE` — её **зеркало для обмена через GitHub**, а не
самостоятельное хранилище. Правка скилла всегда идёт сначала в Hermes, потом
дублируется в архив — никогда наоборот.

Следствие: если версия в архиве и в Hermes разошлись — **права всегда версия из
Hermes**.

---

## 3. Правила синхронизации архив ← Hermes

Когда переносим скиллы в архив перед push, каждый скилл попадает в один из случаев:

| Случай | Что делаем |
|---|---|
| **Имя совпадает, содержимое идентично** | Ничего, архив уже актуален |
| **Имя совпадает, содержимое разошлось** | Кладём в архив свежую версию из Hermes (перезапись) |
| **Скилл переименован / слит** | Сопоставляем по смыслу, решаем какой новее. Новый (из Hermes) заменяет старый: старую папку из архива **удаляем**, новую добавляем |
| **Скилл есть в Hermes, в архиве нет** | Добавляем в архив |
| **Скилл есть в архиве, в Hermes уже нет** | Устарел → **удаляем из архива** (на GitHub только актуальное) |

**Главный принцип:** на GitHub попадают **только самые свежие версии**. Устаревшие
и переименованные предшественники удаляются, а не копятся.

Пример из первичной миграции (17.09.2026): 4 старых узких скилла
(`multithread-downloader`, `playlist-downloader`, `video-extraction`,
`video-url-extractor`) были переработаны в Hermes в 3 более мощных
(`video-fetch`, `video-batch-runner`, `video-source-resolve`). В архиве старые
удалены, новые добавлены.

## 4. Назначение CHANGELOG.md

`CHANGELOG.md` — **журнал изменений архива человеческим языком**. Его цель:
перед push **не гадать**, что изменилось, а видеть готовую сводку — какие скиллы
добавлены, обновлены, переименованы, удалены и когда.

Правило: **каждый раз**, когда архив синхронизируется с Hermes, наверху CHANGELOG
дописывается запись с датой. Формат (шаблон лежит в конце самого CHANGELOG):

```
## ГГГГ-ММ-ДД — краткое описание
Добавлены:     <имя> — <зачем>
Обновлены:     <имя> — <что изменилось>
Переименованы: <старое> → <новое> — <почему>
Удалены:       <имя> — <причина / куда переехало>
```

Git и сам ведёт историю (`git log`, `git diff`), но CHANGELOG читается без git и
объясняет изменения **на смысловом уровне** (git показывает строки, CHANGELOG —
«почему»). Одно дополняет другое.

Куратор Hermes (`hermes curator`) ведёт свои машинные логи в
`C:\Users\<пользователь>\AppData\Local\hermes\logs\curator\<дата>` — что помечено

переименования/доработки делает агент во время сессий, а не куратор.

## 5. Рабочий процесс синхронизации (пошагово)

1. **Инвентаризация.** Сравнить имена и содержимое скиллов в архиве и в
   `…\hermes\skills\` (даты, размер, `diff`).
2. **Классификация** по таблице из §3 (идентичен / обновлён / переименован /
   новый / устарел).
3. **Копирование новых и обновлённых** из Hermes в архив. На Windows/git-bash
   использовать `cp -r`, **не** robocopy в bash-цикле с подстановкой переменной
   `$n` — она не раскрывается и robocopy молча создаёт мусорную папку `skills$n`
   (проверено, обжигались). После копирования вычищать `__pycache__` и `*.pyc`.
4. **Удаление устаревших** папок из архива.
5. **Запись в CHANGELOG.md** — сводка человеческим языком с датой.
6. **Git:** `git add -A`, `git status --short` (обязательно глазами проверить
   состав — нет ли мусора вроде `skills$n`), затем `git commit`, `git push`.
7. **Верификация push:** сверить локальный и удалённый HEAD —
   `git rev-parse HEAD` == `git ls-remote origin main`. Push сообщил «успех» — это
   не доказательство; сверка HEAD — доказательство.

## 6. Перенос архива на другое устройство

На новом устройстве (компьютер 2 / ноутбук):

1. `git clone https://github.com/Yuri-Sverdlov/HERMES-AGENT-SKILL-ARCHIVE.git`
2. Скопировать папки из `skills/` в `%LOCALAPPDATA%\hermes\skills\` с сохранением
   категорий (media/, productivity/, autonomous-ai-agents/ и т.д.).
   Пошаговая инструкция установки, зависимости (Python, Tesseract, cua-driver,
   yt-dlp) и примеры использования — в `README.md`.
3. Перезапустить Hermes (`/new` в чате), чтобы он подхватил новые скиллы.

**Направление всегда одно:** правки — только в директории Hermes, потом в архив,
потом push. Архив на другом устройстве — не место для правок.
