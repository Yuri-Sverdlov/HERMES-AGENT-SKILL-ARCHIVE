## 1. Подключить ПК2 и ноутбук

**Сейчас.** Подключён только ПК1: репозиторий склонирован в
`E:\_MY-PROGRAMMING\HERMES-AGENT-SKILL-ARCHIVE`, Hermes читает его через
`skills.create_dir`, локальные дубли удалены. На ПК2 и ноутбуке скиллы по-прежнему
лежат в `%LOCALAPPDATA%\hermes\skills` и с репозиторием не связаны.

**Почему важно.** Пока это так, синхронизация работает в одну сторону: всё сделанное
на ПК2 и ноутбуке остаётся на них. Новые видеоскиллы (`video-fetch`,
`video-batch-runner`, `video-source-resolve`, `video-compression`) появились
именно на другой машине — там могут быть и другие находки, которых нет в репозитории.

**Как закрыть.** На каждой машине по разделу 6 инструкции. Ключевое — порядок:
сначала уникальные скиллы и правки этой машины переносятся в репозиторий
(сравнение по хешам, а не по датам), и только потом Hermes подключается к папке и
локальные дубли удаляются. Агенту на той машине достаточно сказать: «подключи этот
ПК к репозиторию скиллов, используй скилл `hermes-skills-cross-pc-sync`».

**Нужно от Юрия.** Запустить это на ПК2 и на ноутбуке; подтвердить, что диск `E:`
и путь `E:\_MY-PROGRAMMING\` там есть.

## 3. Смешанная схема размещения скиллов — утвердить

**Сейчас.** Фактически действует так:
- универсальные скиллы — в общем репозитории `HERMES-AGENT-SKILL-ARCHIVE`
  (`create_dir`);
- скилл, привязанный к коду проекта, — в репозитории проекта (`external_dirs`);
  сейчас это один `home-accounting` в `HERMES-ALL-IN-ONE`.

Юрий взял время подумать, окончательно схема не утверждена.

**Варианты.**

| | Всё в общем репозитории | Смешанная схема |
|---|---|---|
| Плюс | одно место, один `git pull` | скилл лежит рядом со своим кодом и меняется одним коммитом с ним |
| Минус | скилл проекта отрывается от кода: абсолютные пути (разные на ПК и VPS), два коммита на одно изменение, команды скилла и кода расходятся; VPS вынужден тянуть все личные скиллы | два места; список проектных скиллов надо вести в README |

**Рекомендация.** Смешанная схема. Обязательное условие: проектный скилл всегда
внутри git своего проекта (иначе повторится история с `immergo-coder`).

**Нужно от Юрия.** «Да» или «нет». После «да» — убрать из
`hermes-skills-cross-pc-sync` пометку «Юрий ещё решает».

## 4. Чат WhatsApp в истории git

**Сейчас.** Репозиторий приватный. Файлы `Чат WhatsApp с контактом +972 … .txt / .zip`
удалены из текущего содержимого, но остались в истории первых двух коммитов
(`4adaa92`, `7a8a39a`): их можно достать командой `git checkout` старого коммита.

**Варианты.**

**Рекомендация.** Если репозиторий когда-либо может стать публичным или общим —
переписать историю сейчас, пока клон один. Если нет — оставить.

## 6. `projects.json` в `overview-projects-on-computer`

**Сейчас.** Скилл хранит в `references/projects.json` список проектов **одного
компьютера** (корень `G:/_MY-PROGRAMMING_1`). Версия с ПК2 (корень `G:/AI`) была
заменена версией ПК1, она осталась в истории git.

**Почему важно.** Скилл описывает конкретную машину, а репозиторий общий: каждый ПК,
обновив свой список, будет затирать список другого, и при `git pull` будут конфликты.

**Варианты.**
- Отдельный файл на каждую машину: `projects.PC1.json`, `projects.PC2.json`,
  `projects.LAPTOP.json`; скрипт `update_projects.py` выбирает файл по имени
  компьютера.
- Вынести список из скилла в репозиторий-хаб `HERMES-AGENT`, а в скилле
  оставить только процедуру.

**Рекомендация.** Отдельный файл на машину — минимальная правка, без конфликтов.

## 15. Мелкие технические улучшения

- **Автоматический CHANGELOG.** Идея из прежней версии `SYNC-LOGIC.md`: раз в неделю
  по расписанию разбирать журнал curator и `git log` и дописывать сводку в
  `CHANGELOG.md`. Не сделано; имеет смысл, если ручные записи перестанут вестись.
- **Окончания строк.** В репозитории смешаны LF и CRLF (git при каждом коммите
  пишет предупреждения `LF will be replaced by CRLF`). Безвредно; убирается файлом
  `.gitattributes` (`* text=auto`) с однократной перенормализацией — лучше
  до подключения других ПК.
- **Выгрузка чата в корне.** `hermes-agent-github-local-ca.json` лежит в папке
  репозитория (исключён `.gitignore`). Можно перенести в папку с другими
  выгрузками, чтобы не путал.
